# Processed data for reproduction

The bundled `data/processed_inputs.tar.gz` provides the machine-readable
inputs used by the training and evaluation code. Raw ETCM web pages and
unrelated source exports are not required for this processed-input workflow.
Run `python tools/prepare_data.py` from the repository root to install them.

| Dataset | Positive input | H-C / C-P / P-D relation files |
|---|---|---|
| TCM-Suite | `TCMsuite/ONE_indices.txt` | `H_C.txt`, `C_P.txt`, `P_D.txt` |
| TCMSP | `TCMSP/one1.txt` | `herb-compound.txt`, `compound-protein.txt`, `target-disease.txt` |
| SymMap2.0 | `Symmap/one.txt` | `HI.txt`, `IT.txt`, `TD.txt` |
| ETCM2.0-mention10 | `ETCM2.0_core_mention10/ONE_indices.txt` | `H_C.txt`, `C_P.txt`, `P_D.txt` |

Paths in this table are relative to `dataset/`. The archive also includes
the unlabelled-pair input files used where applicable, entity mappings, and
the two fixed five-fold compound-disjoint partitions for each dataset.
Sampled unobserved pairs are not experimentally verified negatives.

Numerical inputs and fixed assignment files are byte-identical to the frozen
inputs, with SHA-256 checksums in `data/manifest.json`. The installer changes
only paths and dependent hashes in nine runtime provenance JSON files. A
receipt records each change. Relation rows, labels, compound assignments and
test-fold files remain unchanged.

## ETCM2.0 held-out annotation recovery

The release includes
`dataset/ETCM2.0_validation/validation/ETCM2.0_core_mention10/unseen_confirmed.tsv`,
its source manifest and required entity mappings. All 685 pairs involving
332 compounds are absent from the model C-P graph. These are held-out
annotations from the same resource, not an independent prospective cohort.
The complete archived pair-level ranks are in
`paper_artifacts/results/etcm_confirmed_target_pair_ranks.tsv`.

`configs/sacti_etcm_confirmed_target_evaluation.json` records historical
checkpoint hashes and the evaluation protocol. Checkpoint binaries can be
regenerated by training; `tools/reproduce_etcm_evidence.py` constructs a replay
protocol from the resulting five-fold logs and runs annotation recovery.

## Sources and attribution

The three HDCTI-distributed relation collections were obtained from the
[HDCTI source release](https://github.com/tong87-bio/HDCTI). ETCM2.0 processing
retains source identifiers and applies the recorded connected-core and
`mention_count >= 10` filters. Preparation utilities under `tools/` document
this provenance; they are unnecessary when using the bundle.
